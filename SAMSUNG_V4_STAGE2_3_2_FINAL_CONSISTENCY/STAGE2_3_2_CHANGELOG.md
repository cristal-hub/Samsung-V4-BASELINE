## 4. КОРРЕКЦИЯ №3 — цена фактического исполнения выхода (терминология)

### 4.1. Замечание аудита Stage 2.3.1

Термин `stop_exec_price` использовался как УНИВЕРСАЛЬНАЯ фактическая
цена закрытия (величина №4 таблицы §3 RMF ред. 2.3.1: «Фактическая цена
выхода») — в том числе для TP, BE, TRAIL и стратегических выходов, для
которых цена стопа не применима. Терминологически некорректно и
провоцирует искусственные расчёты «проскальзывания стопа» для
не-стоповых выходов.

### 4.2. Исправление

- Термин `stop_exec_price` ВЫВЕДЕН ИЗ УПОТРЕБЛЕНИЯ. Введены:
  `exit_decision_price` — цена на момент принятия решения о выходе;
  `exit_exec_price` — фактическая цена исполнения выхода, ЕДИНАЯ для
  ВСЕХ типов выхода (SL/TP/BE/TRAIL/стратегический/аварийный),
  средневзвешенная по всем подтверждённым частям.
- `stop_execution_slippage_ps = max(0, sl_price - exit_exec_price)`
  (LONG) — ТОЛЬКО для стоповых инцидентов (триггер — защитное
  срабатывание SL, FSM STOP_DETECTED, включая эскалационные ноги того же
  инцидента); для остальных типов выхода поле = NOT_APPLICABLE, а НЕ
  искусственно рассчитанное значение. Дополнительно публикуется
  знаковое `stop_price_deviation_ps = sl_price - exit_exec_price`
  (>0 — хуже стопа, <0 — лучше стопа; обрезка max(0,…) не скрывает
  благоприятный факт).
- Общее проскальзывание выхода: `exit_slippage_ps =
  close_price_before_order - exit_exec_price` — для ВСЕХ типов выхода.
  Знаки и единицы определены явно: ценовые единицы на одну акцию; LONG
  положительное = неблагоприятное. Существующее денежное CSV-поле
  `exit_slippage` (main.py:2466) сохраняет имя и единицы; конфликт имён
  исключён суффиксом `_ps` у контрактных пер-шарных полей.
- Частичные исполнения (§5.5 RMF — новый раздел): учитывать каждое
  подтверждённое исполнение; хранить количество и цену каждого;
  средневзвешенная итоговая цена; цена отправленной заявки НЕ считается
  ценой исполнения; цена отменённой заявки НЕ считается исполнением;
  ранее подтверждённые части не теряются; неизвестные цены исполнения
  НЕ заменяются ценой решения или ценой заявки (прецедент В3:
  price_confirmed=False → CSV без P&L — main.py:1975-2011).
- Согласованность отчётности: обновлены risk model (RMF §3/§4/§5/§6/§8/§9),
  OrderLedger (заявки инцидента с incident_id — события публикуют новые
  поля), research_trades.csv/учёт закрытия (поля согласованы с

  reconciliation (неподтверждённые части не включаются в средневзвешенную),
  тестовая матрица (T-15, RM-08/RM-09 обновлены; RM-15…RM-17 новые).
- Двойной учёт проскальзывания исключён правилом **DC-7** (матрица §6
  RMF): поля exit_slippage_ps/stop_price_deviation_ps/
  stop_execution_slippage_ps — наблюдаемые величины и НЕ добавляются к
  realized_loss как члены (симметрично DC-2).
- Входная формула риска НЕ изменена: исправление ред. 2.3.1
