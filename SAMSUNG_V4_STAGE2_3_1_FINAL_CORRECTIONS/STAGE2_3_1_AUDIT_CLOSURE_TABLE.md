## 1. Критическая коррекция №1 — точка интеграции EmergencyExitController

**Формулировка аудита (ТЗ §3.1):** контроллер описан как механизм,
запускаемый ПОСЛЕ существующего защитного выхода check_all(); по
фактической последовательности кода первая рыночная SELL отправляется до
него, гибридная последовательность «лимит → рынок» не выполняется.

| Требование аудита | Решение Stage 2.3.1 | Документы / разделы | Тесты |
|---|---|---|---|
| Контроллер получает Stop Event ДО первой заявки | Шаг 2г цикла передаёт решения контроллеру (один Exit Incident + INTENT, БЕЗ заявок); первая попытка — только в шаге 2д после reconciliation | EEA §3 (маршрут), §7 этап A/B; Blueprint §6.2 (2г/2д); FILE_CHANGE_MAP M-7 | EE-01, EE-02; B-6 |
| check_all() не способен обойти контролируемый маршрут | check_all сохранён как ТОЛЬКО обнаружитель (контракт execution.py:978-1022 не меняется); запрет обхода зафиксирован на уровне ЦИКЛА — прямой вызов close_position для to_close удалён из проекта | EEA §3 (запрещённые схемы п. 4-5), §9; Blueprint §6.2; TRACEABILITY §2.10 (F-30) | EE-04; B-6 (инструментированный журнал вызовов) |
| Нет двух конкурирующих механизмов отправки SELL | ЕДИНСТВЕННАЯ точка отправки закрывающих заявок — process_incidents; close_position — исполнитель рыночной ноги ВНУТРИ контроллера; одна активная заявка на инцидент; `_sell_block_reason` переиспользуется | EEA §3, §8 (I-5, I-9), §9; FILE_CHANGE_MAP §3.8 | EE-04, EE-05, EE-10; правило §6.3.8 |

## 2. Критическая коррекция №2 — модель риска

**Формулировка аудита (ТЗ §4.1):** утверждение Stage 2.3 «фактическое
входное проскальзывание уже содержится в |exec_price - sl|» некорректно,
если Stop Loss рассчитывается от exec_price: расстояние до стопа
характеризует риск движения от фактической цены входа до стопа, а не
отклонение цены исполнения от цены принятия решения.

| Требование аудита | Решение Stage 2.3.1 | Документы / разделы | Тесты |
|---|---|---|---|
| Разделить четыре ценовые величины (decision_price / exec_price / sl_price / stop_exec_price) | Четыре величины определены с источниками file:line, моментом появления, правилами неизвестных значений; entry_slippage = exec_price - decision_price (LONG: положительное = неблагоприятное; нормализация цена/акцию; знаки согласованы с существующим CSV-учётом main.py:2464-2466) | RMF §3; Blueprint §7.4 (поля журнала); TRACEABILITY §2.10 (F-31) | RM-01…RM-04 |
| Разделить семь составляющих риска | C1…C7: плановое расстояние / фактическое расстояние / входное проскальзывание / комиссия входа / оценочная комиссия выхода / резерв стоп-исполнения / фактическое проскальзывание выхода — каждая с единицами, моментом, источником; смешение запрещено | RMF §4 | RM-01…RM-09 (по составляющим) |
| Три модели риска | ESTIMATED (до входа), OPEN ESTIMATED (после регистрации), REALIZED (после выхода) — с формулами, единицами, временными точками, источниками параметров, обработкой неизвестных (факт комиссии неизвестен → модельная оценка с пометкой, НЕ ноль) | RMF §5; Blueprint §7.4 | RM-05…RM-09, RM-13 |
| Связь с sizing; без двойного учёта | Sizing-контракт не меняется (golden); SLIPPAGE_PERCENT — только в знаменателе (DC-1); entry_slippage — отдельное поле, НЕ член open-риска (DC-2 — обоснование ред. 2.3 исправлено); резерв ≠ расстояние (DC-5); разница знаменателя sizing и модели публикуется (risk_model_sizing_gap_ps); D-28 | RMF §6 (DC-0…DC-6), §7; Blueprint §7.4 | RM-10, RM-11, RM-12 |
| Превышение риск-бюджета после исполнения — отдельное событие | RISK_BUDGET_EXCEEDED (estimated/open/planned/budget); реакция v1 — журналирование (D-15); автоматическая продажа/изменение позиции НЕ проектируется без решения владельца | RMF §7.3; Blueprint §7.4; OPEN_DECISIONS D-15 | RM-13 |
| Формулы: единицы/время/источники/неизвестные/запрет двойного учёта/размерная корректность + числовой пример | Для каждой формулы указаны единицы (цена/акцию, руб.), временная точка, входные параметры с источниками, обработка неизвестных; числовой пример с УСЛОВНЫМИ данными просчитан программой (Decimal) — демонстрирует различие четырёх цен и декомпозиции realized↔open↔estimated; пример НЕ является рекомендуемыми параметрами | RMF §5, §8; TRACEABILITY §2.10 (арифметика VERIFIED) | §9 целиком; эталон арифметики — RM-тесты воспроизводят §8 байт-в-байт |
| Резерв stop slippage — сохранить как отдельный параметр, без числового значения | STOP_SLIPPAGE_RESERVE сохранён отдельным членом (D-16); значение НЕ установлено; до решения — явная пометка unconfigured и явное утверждение «расчётный риск НЕ является полным прогнозом гэп-риска» | RMF §5.4, §9; EEA §11; OPEN_DECISIONS D-16, D-28 | RM-11 |
