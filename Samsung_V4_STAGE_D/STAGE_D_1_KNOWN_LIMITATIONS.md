# STAGE D.1 — KNOWN LIMITATIONS

Наследуются из Stage D (не изменились) и дополняются наблюдениями
аудита D.1. Ни одно ограничение не является дефектом расчёта; все они
осознанные границы архитектуры.

## Наследованные ограничения Stage D

1. **LONG-only**: SHORT-масштабирование явно не поддерживается
   (UNSUPPORTED_SIDE); «стоп выше входа» для SHORT не обрабатывается.
2. **Чистый расчёт**: результат — не ордер и не команда исполнения;
   трансформация в заявку вне Stage D запрещена (ТЗ §9).
3. **Свежесть цен не проверяется** в Stage D (staleness — зона
   ответственности Stage C price gate); Stage D валидирует
   корректность значений, FIGI-согласованность и геометрию стопа.
4. **Консервативный расход buying power** (на единицу — notional +
   входная комиссия): возможен чуть более строгий объём, чем при
   «в лоб» формуле без комиссии.
5. **Float-зеркала денежных полей** — отображение; при экстремальных
   порядках отдельное float-поле может отличаться от точного значения
   на 1 ulp (или быть None, если непредставимо). Точные значения
   ВСЕГДА в diagnostics строками (Decimal); на решения не влияют.
6. **Явный ноль затрат — данные** (нулевая комиссия); неизвестность —
   только None (блокирует расчёт MISSING_REQUIRED_DATA).
7. **Нет портфельных лимитов** (на количество позиций/суммарный
   риск) — только явные доли риск-политики и buying power.

## Наблюдения аудита D.1 (не дефекты, зафиксированы для полноты)

8. **`REASON_QUANTITY_BELOW_ONE_LOT` — зарезервированный код**: ни
   один путь расчёта его не возвращает (каждый ZERO_SIZE получает
   конкретную причину RISK_BUDGET/NOTIONAL_CAP/BUYING_POWER_BELOW_ONE_LOT).
   Оставлен в публичном словаре причин для стабильности API; удаление
   без необходимости не выполнялось.
9. **Диапазон buying power**: [0; +inf) — ноль это валидные данные
   («средств нет» → ZERO_SIZE/BUYING_POWER_BELOW_ONE_LOT), а не
   отсутствие данных (отсутствие = None → MISSING_REQUIRED_DATA).
10. **Собственный тест Stage D §10.17 покрывал только prec/rounding** —
    в D.1 покрытие расширено: hostile Emax/Emin/rounding/traps
    (включая отключенный Overflow-trap и включенные
    Inexact/Rounded/Clamped/Subnormal/Underflow-traps) — теперь
    инвариант проверяется по всем параметрам контекста.
11. **Средовая зависимость полного прогона**: тесты Stage A/B/C
    (G-1/golden-сигналы) при отсутствии пакета `pandas_ta_classic`
    деградируют в SKIP (18 FAIL / 35 SKIP в чистой среде — средовые,
    вне Stage D). Для счётчиков baseline (1553/1033) требуется
    `pip install pandas-ta-classic`. Сам Stage D и его тесты от пакета
    НЕ зависят.
12. **Экстремальные int-входы**: целые вне диапазона float (например,
    10**400) отклоняются контролируемой ошибкой валидации
    (SizingInputViolationError) — осознанное решение: десятичная модель
    входа построена от float/int в диапазоне float; произвольная
    точность целых не требуется контрактом Stage D.

## Статус

Stage D.1 реализован и передаётся на независимую проверку. **Не
заявляется принятым.** Stage E не начинался.
