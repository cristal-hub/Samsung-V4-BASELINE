# KNOWN LIMITATIONS — STAGE C.1

Дата: 2026-11-28. Ограничения Stage C (KNOWN_LIMITATIONS_STAGE_C.md)
наследуются полностью; ниже — только новое, специфичное для C.1.

1. **Порядок проверки config_hash при блокирующей цене изменился
   детерминированно.** При ОДНОВРЕМЕННО плохой цене И несовпадающем
   config_hash сохранённого состояния раньше первым поднимался
   `StateConfigMismatchError` (get_state шёл раньше price gate); теперь
   первым возвращается `INCOMPLETE_PRICE_EVALUATION` (price gate раньше),
   а `StateConfigMismatchError` поднимается только при валидной цене.
   Это ТРЕБУЕМЫЙ порядок ТЗ Stage C.1 §3 (п. 3-4: при блокирующей цене
   состояние не запрашивается). Отдельного теста на такую комбинацию в
   ТЗ не было; поведение следует явно из фиксированного порядка.

2. **Межпроцессная блокировка StateStore** — унаследованное ограничение
   Stage B.1 (документировано там): координатор полагается на
   атомарность `update_state`/`get_or_create` Stage B.1 в пределах
   процесса; межпроцессная конкуренция по-прежнему не поддерживается
   (Stage C.1 не меняет Stage B.1).

3. **Отчёт при блокирующей цене не содержит данных состояния** — по
   построению: `manager.get_state` не вызывается, поэтому в
   `ExitDecisionReport` нет снимка состояния. Диагностика блокировки
   самодостаточна (причина цены + пометка `evaluators_called=False`).

4. **`_json_file_names()` в тестах рассчитана на пустой tmp_path** —
   тесты сценариев 1-3 создают StateStore на выделенном `tmp_path`
   pytest, поэтому подсчёт `*.json` корректен; на общий каталог с
   посторонними файлами тест не рассчитан (так не используется).

5. **Диапазон корректности возрастной проверки цены** — не изменился:
   точность ограничена точностью метки времени `PriceData.timestamp`
   и переданным `now`; проверка осталась в `check_price` Stage C.
