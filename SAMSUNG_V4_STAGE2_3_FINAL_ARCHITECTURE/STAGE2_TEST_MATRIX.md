## 7. Критерии приёмки этапа (общие)

Этап считается принятым, когда:
1. все пункты матрицы, назначенные этапу (колонка «Этап»), зелёные;
2. полный pytest зелёный (789 существующих + новые);
3. golden-пункты соответствующего этапа дают нулевой diff торговой логики;
4. SHA256 всех изменённых файлов зафиксирован (SHA256SUMS_stage2-<буква>.txt);
5. решение владельца, назначенное этапу в roadmap, зафиксировано письменно.

Любой красный пункт = этап не принят -> исправление в рамках того же
этапа (не «поверх» следующим этапом) -> повторный полный прогон.
## 8. Аварийный выход (Stage 2.3, коррекция №4; EE-01…EE-17 — STAGE2_EMERGENCY_EXIT_ARCHITECTURE.md §9)

Обязательная новая часть архитектуры: EmergencyExitController — гибридный
механизм «контролируемая попытка выхода -> эскалация к рыночной заявке».
Для каждого сценария проверяются ЧЕТЫРЕ состояния: (1) позиция
(остаток/статус), (2) заявка (статус/идентификаторы), (3) журнал
(события/хронология инцидента), (4) состояние системы (UNCERTAIN/норма).
Все тесты выполняются на мок-adapter (без брокера); этап реализации — H
(STAGE2_IMPLEMENTATION_ROADMAP.md). Расширение адаптера (лимитная заявка)
