## 5. Архитектура конфигурации

```
runtime.env (.env)  ← секреты/токены; в конфигурации движка НЕ участвуют
engine.json         ← основной источник: ACTIVE_STRATEGY (+ версия схемы,
                      ключи-комментарии с префиксом "_" игнорируются)
os.environ[ACTIVE_STRATEGY] ← переопределение поверх engine.json
        │
        ▼
engine_config.load_engine_config()  ──►  EngineConfig (неизменяемый отчёт):
        status: UNCONFIGURED | CONFIGURED | CONFIG_ERROR
        active_strategy, active_strategy_source, errors, warnings
        attribution: AttributionContext(strategy_id, config_hash) | None
        trading_allowed == (status is CONFIGURED)
        │
        ▼
require_trading_ready(cfg) ──► AttributionContext  (шлюз торгового режима;
                                Этап A всегда отклоняет: активируемых
                                стратегий нет)
```

Ключевые решения:

1. **Приоритет источника** (документирован в докстринге модуля, в
   `engine.json`, в README): env `ACTIVE_STRATEGY` > `engine.json` >
   UNCONFIGURED. Пустая/пробельная env считается НЕ заданной (явно
   задокументировано, торговый режим в любом случае остаётся заблокирован).
2. **UNCONFIGURED** — состояние поставляемого `engine.json` (`null`):
   разрешены offline-тесты и проверка архитектуры; торговый режим запрещён
   (`trading_allowed=False`, `require_trading_ready` raises).
3. **CONFIG_ERROR (fail-closed)** при: битом JSON (env НЕ «спасает» битый
   файл); JSON-не-объекте; нестроковом `ACTIVE_STRATEGY`; неизвестной
   стратегии; известной, но regression-only стратегии (legacy_samsung_v4).
4. **Никаких скрытых fallback**: отсутствие значения не подменяется
   умолчанием; неизвестные ключи engine.json дают предупреждение и не
   влияют на поведение.
5. **Реестр стратегий** (`strategies/__init__.py`): регистрация только
   явная (`register_strategy`), `activatable_strategy_ids()` на Этапе A
   всегда пуст → любое непустое значение ACTIVE_STRATEGY даёт ошибку
   конфигурации. Автовыбор отсутствует по построению.
6. **Секреты не участвуют**: движок читает только `ACTIVE_STRATEGY`
   и собственные ключи `engine.json`; runtime.env/.env не читается
   `engine_config.py` вообще.

## 6. Алгоритм вычисления config_hash

Реализация: `strategy_api.compute_config_hash()`.

- **Алгоритм:** SHA-256.
- **Вход (точно и только это):** канонический JSON-документ вида
  `{"config_hash_version": 1, "hash_algorithm": "sha256",
  "strategy_id": …, "strategy_version": …, "params": {…}}`.
- **Канонизация:** `json.dumps(sort_keys=True, separators=(",", ":"),
  ensure_ascii=False, allow_nan=False)`; ключи-словари сортируются на любом
  уровне вложенности → порядок ключей исходного JSON не влияет на hash;
  кортежи/множества нормализуются к спискам (множества — в отсортированном
  порядке), Enum — к своим значениям.
- **Нормализация типов:** параметры предварительно нормализуются по
  спецификациям стратегии (`ParamSpec`: int → int (bool отвергается),
  number → float), поэтому «60» и 60.0 для number-параметра дают одинаковый
  канонический hash (проверено тестами).
- **НЕ участвуют:** секреты/токены/пароли, содержимое runtime.env/.env,
  переменные окружения, пути файлов, текущее время, случайные значения,
  машинные недетерминируемые типы (отвергаются ошибкой).
- **Свойства, покрытые тестами:** одинаковая конфигурация → одинаковый hash;
  изменение значимого параметра → другой hash; порядок ключей не влияет;
  изменение strategy_id/strategy_version меняет hash; NaN/Infinity → ошибка.

## 7. Принцип работы ACTIVE_STRATEGY

- Значение задаётся ТОЛЬКО вручную (engine.json или переменная окружения).
- Пустое значение в обоих источниках → UNCONFIGURED (торговля запрещена,
  offline разрешён).
- Неизвестное значение → CONFIG_ERROR с перечнем известных id и явным
  текстом «автоматический выбор запрещён».
- `legacy_samsung_v4` известен реестру, но отклоняется: regression-only,
  не для торгового режима.
- На Этапе A список активируемых стратегий пуст → ЛЮБОЕ непустое значение
  отклоняется. Появление реальной стратегии (Этап B/C) добавит её в реестр
  ЯВНОЙ регистрацией с `activation_mode=TRADING_ALLOWED, activatable=True`.

## 8. Способ изоляции legacy regression adapter

1. **Реестр:** `strategies.legacy_samsung_v4` регистрируется с
   `regression_only=True, activatable=False`; `activatable_strategy_ids()`
   его не возвращает; движок не может его активировать.
2. **Ограничение origin:** usable-конфигурация адаптера создаётся ТОЛЬКО
   методом `build_regression_config(profile_name)` (origin=«regression_harness»);
   `evaluate_entry` и `get_config` отвергают origin=«engine»
   (`LegacyRegressionError`).
3. **Без копирования логики:** адаптер вызывает ОРИГИНАЛЬНЫЙ baseline-модуль
   `strategy.py` (`StrategyManager.get_signal`); торговая логика не
   дублируется и не переизобретается.
4. **Временные параметры:** на время регрессионного вызова параметры профиля
   устанавливаются в загруженный модуль `config` контекст-менеджером
   `_override_legacy_config` с восстановлением исходных значений в `finally`
   (включая случай исключения). Файл `config.py` не изменяется; после вызова
   baseline-состояние (включая исторический `PROFILE="FORCE_TRADE"`)
   побайтово нетронуто — покрыто тестом.
5. **Ленивые импорты:** `pandas_ta_classic` и baseline `strategy.py`
   импортируются только при реальном регрессионном вызове — загрузка
   реестра/конфигурации не требует торговых зависимостей.
6. **Только offline:** адаптер не выполняет сетевых действий и не создаёт
   заявок; FORCE_TRADE не переносится и в тестах нового движка не
   используется (профиль отсутствует в `profiles.py`, запрос даёт
   `ValueError`).

## 9. Подтверждение отсутствия FORCE_TRADE в новой архитектуре

- В коде новой архитектуры (`strategy_api.py`, `engine_config.py`,
  `attribution.py`, `strategies/**`) FORCE_TRADE отсутствует КАК
  функциональный элемент: нет профиля, нет режима, нет тестового
  переключателя, нет альтернативной стратегии; `profiles.PROFILE_NAMES ==
  ("SANDBOX_TEST", "TECH_CHECK", "CONSERVATIVE")`;
  `build_regression_params("FORCE_TRADE")` → `ValueError` (тест G-5).
- Упоминания строки «FORCE_TRADE» в новых файлах — ТОЛЬКО в
  комментариях/докстрингах, объясняющих, что механизм сознательно не
  перенесён (это требование ТЗ §3: «не расширять их» относится к
  функциональности; текст-пояснение функциональностью не является).
- Исторические упоминания в baseline (`config.py`: `PROFILE = "FORCE_TRADE"`)
  не изменены и не расширены — файл байт-идентичен baseline.
- Тесты нового движка FORCE_TRADE не используют (проверяется фактом
  отсутствия профиля в реестре профилей).

## 13. Все отклонения от ТЗ

1. **`t-tech-investments==1.51.0` не установлен**: пакет отсутствует в
   публичном PyPI (окружение исполнения). Для этого SDK действует штатная
   заглушка `tests/conftest.py` baseline (созданная авторами baseline
   именно для чистых окружений). Влияние на Этап A: нет (новый код этот SDK
   не использует).
2. **Версия pandas-ta-classic**: ограничение `>=0.3.14b`; точная версия
   `0.3.14b0` в PyPI отсутствует, `0.3.14b1` несовместима с numpy 2.x
   (`from numpy import NaN`), установлена **0.3.15** (удовлетворяет
   заявленному ограничению). Влияние на golden-эталон G-1: значения reasons
   снимались в этой версии; при смене версии индикаторов эталон может
   потребовать пересборки штатным генератором (см. ROLLBACK/README).
3. **Атрибуция НЕ встроена в производственный поток** (main/execution/logger).
   ТЗ §11 требует не расширять объём самостоятельно, если безопасное
   внедрение требует изменения механизма исполнения/хранения состояния.
   Внедрение атрибуции в `research_trades.csv` требует добавления полей в
   `TRADE_FIELDS`, что на машинах пользователей вызывает штатную
   авто-ротацию шапки журнала (`research_trades_<stamp>.bak.csv`) —
   это изменение поведения пользовательских данных, выходящее за «минимальные
   изменения» Этапа A. **Зафиксированный блокер и минимальное решение:**
   в Этапе B добавить `strategy_id, config_hash` В КОНЕЦ `TRADE_FIELDS`
   (механизм авто-миграции logger.py уже сохраняет старый журнал как .bak),
   либо писать атрибутированные строки только новыми путями движка
   (`attribution.append_attributed_csv_row` — готов и покрыт тестами);
   для JSONL-событий атрибуция совместима уже сейчас (`stamp` + payload).
4. **`orders.zip` исключён из поставки** (байт-идентичный файл baseline):
   внутри — реальные пользовательские runtime-файлы владельца
   (`state.json`, `order_ledger.jsonl`, `research_events.jsonl`,
   `research_trades.csv`, `main_console.txt`), что прямо запрещено ТЗ §14
   («реальные пользовательские runtime-файлы; state.json; реальные журналы
   сделок»). Файл остаётся в baseline-источнике нетронутым; SHA-256
   совпадает с baseline (документировано в BASELINE_VS_CANDIDATE.md).
5. **G-1 в окружении-2 (чистые заглушки)** честно помечается SKIP:
   эталон снят реальными индикаторами и не воспроизводим на пустой
   заглушке `pandas_ta_classic`. Это не «скрытый провал»: статус SKIP
   виден в протоколе, причина указана.

Иных отклонений нет.
